# Conversational save with exact-version arXiv import

Status: superseded for the active study workflow by explicit plugin selection, manual paper/PDF acquisition, offline arXiv lookup, and conversation-local targets. This record remains authoritative for the retained legacy import operations and their historical outcomes.

## Context

The researcher starts from an arXiv URL in ChatGPT Web and later asks to save the proof, question, and references. Requiring a repeated bridge path or a manual connection prompt does not meet that experience. The approved first distribution reuses an existing authenticated Mac Safe Files connection; a general Mac installer and other source publishers remain outside this extension.

## Decision

Package a private personal ChatGPT workflow with the existing Mac app dependency, matching Zotero XPI, and portable plain-text client kit. Only the private plugin instance stores the bridge root. Typed `inspect_arxiv` and `ensure_arxiv_pdf` operations resolve a concrete version and obtain or reuse its PDF through Zotero-host acquisition and native APIs. A clear save request includes necessary import of the studied paper into personal My Library root; studying alone does not write. References remain links unless their import is separately requested.

Keep acquisition, staging, native persistence, file transport, and conversation instructions behind replaceable boundaries. Serialize and bound source requests, honor service cooldowns, validate every resource route, and preserve native planned identities and operation outcomes. A retained parent and an unknown commit are distinct from a ready PDF. Full study text stays beside its passage and must survive exact readback or be rejected before mutation.

## Alternatives

A new hosted MCP or generic local runner would add transport/authentication and installation work outside the approved first release. Switching to Codex or requiring a plugin mention for every save would change the agreed ordinary-Web workflow. A generic downloader, direct SQLite writes, and PDF-byte annotation edits bypass the selected authority and native-data boundaries.

## Consequences

There are two installable product components plus an independently supplied Mac connection. Private account exports must not replace portable artifacts. Ordinary account activation, native PDF readiness, exact annotation storage, and actual reader display need separate evidence. Local tests and direct-file success cannot establish ordinary-Web acceptance; unresolved platform selection remains a completion blocker. Public publication, project licensing, a public Mac installer, and independently validated Work behavior remain separate decisions.
