# Owned native acceptance diagnostics

This directory contains narrowly scoped, temporary host diagnostics. Keep them separate from the production extension and its distributed client protocol.

- Each diagnostic has fixed, reviewable actions and deliberately owned fixtures. Never accept arbitrary commands, evaluation, transport requests, URLs, or user paper targets. Installation and startup must not perform writes.
- Use production ports and native adapters for the behavior under test. Controlled faults and synthetic source identities must be labeled explicitly; they do not establish real network acquisition or ordinary ChatGPT Web behavior.
- Preserve fixed operation identities, a separate durable diagnostic journal, and minimal private results across restart and ordinary removal. Resolve runtime paths through host APIs; never embed a developer home directory, credentials, or profile contents.
- Native mutations require the existing authorization and conflict boundaries. Do not modify SQLite, PDF bytes, existing user content, or production operation history.
- Before installation, independently review the complete source and deterministic XPI contents. Document the exact commands, expected native effects, limitations, result checks, and normal removal procedure in English.
- Run offline package assertions and the project verification command. Actual host claims require evaluated results from Zotero; an unevaluated check is not a pass.
